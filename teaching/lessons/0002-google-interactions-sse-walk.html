Walk Google Interactions SSE

Same API you use in batch; add stream: true and consume events.

Lesson 0001 · Glossary · Spike: apps/backend/spikes/google-interactions-sse-walkthrough.ts

Batch vs stream (one call site)

Today GoogleAgentProvider awaits one object with interaction.steps. With streaming, create returns an async iterable of SSE events. After the stream ends, non-stream steps are the assembled picture of those events.

Event timeline

interaction.created     → id, status in_progress
  (step.start → step.delta* → step.stop)+   → per "step" (thought, model_output, function_call, …)
interaction.completed   → usage, status completed

Source: Streaming interactions.

Step types you will see

  • thought — may stream before answer; deltas often not user-facing.
  • model_output — step.delta with type: "text".
  • function_call — name on step.start; args via arguments_delta strings.

Handler sketch (maps to spike)

for await (const event of stream) {
  if (event.event_type === "step.delta" && event.delta?.type === "text")
    emit text to UI
  if (event.event_type === "step.delta" && event.delta?.type === "arguments_delta")
    acc += event.delta.arguments   // batch gate: parse after step.stop
  if (event.event_type === "step.start" && event.step?.type === "function_call")
    show "calling …"
}
