Lesson 0006 · Mission: Agent Skills

A skill is not a tool

One win: you can name the three load levels and map Level 2 onto read_file.

Glossary · Cheatsheet · Mission

1. Read this first (primary source)

Format and load order live in the open spec, not in the paper: Agent Skills specification. Same three-stage story in Anthropic’s overview (metadata always; body when triggered; extra files as needed).

The PDF you sent, Ling, Zhong, Huang 2026, measures 40,285 public listings. Use it for scale, redundancy, and risk — Appendix A only restates the same index-then-load pattern.

2. Two different objects

Tool — JSON schema the model calls. This repo already has read_file, write_file, list_dir in apps/backend/src/tools/fsTools.ts.

Skill — a folder with SKILL.md. YAML says when to use it. Markdown says how. Optional scripts and references sit beside it.

Skills tell the model which tools to use and in what order. They do not replace the tool registry. Paste-every-skill into AGENT_SYSTEM_PROMPT collapses that distinction and burns the context window.

3. Progressive disclosure (the only load design)

  1. Discovery. At session start, inject only name + description for each installed skill (~100 tokens each, Anthropic). That is the discovery index.
  2. Activation. User request matches a description. Model reads the matching SKILL.md. In this harness that is an ordinary read_file on a path inside the workspace jail — no new vendor “skill tool” required for the first version.
  3. Execution. Follow the body. If it points at references/FORMS.md or scripts/extract.py, read or run that file then. Scripts stay on disk; only their output should enter context.

Paper Figure 2: median skill is 1,414 tokens; a 1% tail exceeds 9,253; max in that crawl is 116,239. Loading every body up front does not scale. Spec advice: keep the main file under 500 lines; split the rest.

4. What your loop does today

workspaceSystemPrompt is static text plus three fs tools. There is no skill index. That is the gap — not “missing function-calling.” First integration is: scan skill dirs, put metadata in the prompt, tell the model to read_file the SKILL.md when the description matches. Do not implement that this lesson.

5. Safety (from the paper, not folklore)

Same snapshot, LLM audit: 54% L0, 5% L1, 30% L2, 9% L3. Nearly two fifths can touch private data or change state. Anthropic: treat untrusted skills like installing software; a skill can steer existing tools into harm. Your jail on workspace paths is necessary and not sufficient if a skill says “exfiltrate then delete.”
