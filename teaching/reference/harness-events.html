HarnessEvent enum

Source of truth: apps/backend/src/abstraction/types.ts

Glossary · Lesson 0002

Variants

  • turn_started — stream open; optional provider interaction id.
  • text_delta — assistant-visible token(s).
  • tool_call_ready — args complete; safe to execute tool.
  • message_complete — full assistant text for this provider turn.
  • turn_completed — provider stream closed; status + usage.
  • tool_run_started / tool_run_finished — agent loop, not Google SSE.
  • error — parse failure, API error, aborted stream.

Who emits what

Google mapper     → turn_started, text_delta, tool_call_ready,
                    message_complete, turn_completed, error
Agent loop        → tool_run_*, forwards provider events
HTTP/CLI adapter  → forwards all (optional filter thought)

Google Interactions → HarnessEvent

interaction.created           → turn_started { providerInteractionId }
step.delta type=text          → text_delta
step.start type=function_call → (optional UX only; wait for ready)
step.stop after function_call → tool_call_ready (parse accumulated args)
interaction.completed         → turn_completed { status, usage }
  requires_action + tool_call_ready already sent → agent runs tool, new stream
  completed + text accumulated  → message_complete then turn_completed

Ignore thought steps and thought_signature deltas unless you add a separate debug channel.

Agent loop consumption

for await (const e of provider.converseStream(conv)) {
  forward e to subscriber
  if (e.type === "tool_call_ready") {
    emit tool_run_started → execute → tool_run_finished
    break inner stream; append result; next converseStream
  }
  if (e.type === "message_complete") return e.text
}

Helpers: toolCallReadyToInteractionStep, messageCompleteToInteractionStep bridge batch-shaped code.
